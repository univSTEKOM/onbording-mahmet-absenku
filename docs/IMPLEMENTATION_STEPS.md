# Implementation Steps — Sistem Absensi Karyawan

## Fase 1: Init Project

### Step 1 — Create React + Vite + TypeScript project
```bash
npm create vite@latest frontend -- --template react-ts
cd frontend
npm install
```

### Step 2 — Install dependencies
```bash
# Core
npm install react-router-dom @tanstack/react-query axios

# Icons
npm install lucide-react

# Face recognition
npm install face-api.js

# Dev
npm install -D tailwindcss @tailwindcss/vite
```

### Step 3 — Setup Tailwind CSS
- Configure Tailwind in `vite.config.ts`
- Add Tailwind directives to `src/index.css`

### Step 4 — Setup shadcn/ui
```bash
npx shadcn@latest init
```
- Choose: New York style, Neutral color
- Install base components: Button, Card, Input, Badge, Table, Dialog, Select, Form, Toast, Avatar, DatePicker

### Step 5 — Setup folder structure
Create directories:
```
src/api/
src/components/ui/        (auto-generated by shadcn)
src/components/layout/
src/components/shared/
src/contexts/
src/hooks/
src/lib/
src/pages/
src/types/
```

### Step 6 — Setup React Router (App.tsx)
- Define route tree: public routes (login, register), protected routes (karyawan + admin)
- Setup BrowserRouter, Routes, Route

### Step 7 — Setup TanStack Query (main.tsx)
- Create QueryClient with default options
- Wrap App with QueryClientProvider

### Step 8 — Create .env file
```
VITE_API_URL=http://localhost:3001
```

## Fase 2: Mock API

### Step 9 — Create db.json
- File: `mock-api/db.json`
- Seed data: 3 users (1 admin, 2 karyawan), 6 absensi records, 2 pengajuan
- Sesuai skema di DATABASE_PLAN.md

### Step 10 — Create server.js
- File: `mock-api/server.js`
- json-server instance with custom routes
- Custom POST `/api/auth/login` — find user by email + password
- Custom POST `/api/auth/register` — create new user
- Enable CORS

### Step 11 — Add json-server script
```bash
npm install -D json-server
```
- Add to mock-api/package.json or root scripts
- Script: `json-server --watch db.json --port 3001 --middlewares ./server.js`

### Step 12 — Test endpoints
- Test GET /users, GET /absensi, GET /pengajuan
- Test POST /api/auth/login, POST /api/auth/register
- Test POST /absensi (check-in), PATCH /absensi/:id (check-out)
- Test POST /pengajuan, PATCH /pengajuan/:id (approve/reject)

## Fase 3: Foundation Code

### Step 13 — TypeScript interfaces (src/types/index.ts)
Define interfaces:
- User: id, email, password, nama, jabatan, role, foto, phone, alamat, createdAt
- Absensi: id, userId, tanggal, checkIn, checkOut, status, faceVerified, keterangan, createdAt
- Pengajuan: id, userId, jenis, tanggalMulai, tanggalSelesai, alasan, status, catatan, createdAt
- LoginRequest, RegisterRequest, LoginResponse
- AbsensiFormData, PengajuanFormData

### Step 14 — Axios instance (src/api/axios.ts)
- Create axios instance with baseURL from `import.meta.env.VITE_API_URL`
- Add request interceptor to attach fake token from localStorage
- Add response interceptor for error handling (401 redirect to login)

### Step 15 — API service files
- `src/api/auth.ts` — login(), register()
- `src/api/users.ts` — getUsers(), getUser(), updateUser()
- `src/api/absensi.ts` — getAbsensi(), getAbsensiByUser(), getAbsensiToday(), checkIn(), checkOut()
- `src/api/pengajuan.ts` — getPengajuan(), getPengajuanByUser(), createPengajuan(), updatePengajuanStatus(), deletePengajuan()

### Step 16 — AuthContext (src/contexts/AuthContext.tsx)
- State: user (User | null), token (string | null), isLoading
- Actions: login(email, password), register(data), logout()
- On mount: check localStorage for saved user + token
- Provide: user, token, isLoading, login, register, logout, isAdmin

### Step 17 — useAuth hook (src/hooks/useAuth.ts)
- Shortcut to consume AuthContext
- Include role check helpers: isKaryawan, isAdmin

### Step 18 — TanStack Query hooks
- `src/hooks/useAbsensi.ts` — useAbsensiList(userId, filters), useAbsensiToday(userId), useCheckIn(), useCheckOut()
- `src/hooks/usePengajuan.ts` — usePengajuanList(userId), useCreatePengajuan(), useUpdatePengajuanStatus(), useDeletePengajuan()
- `src/hooks/useUsers.ts` — useUser(id), useUpdateUser()

### Step 19 — Route guard components
- `ProtectedRoute.tsx` — check if logged in, redirect to /login
- `AdminRoute.tsx` — check if role = admin, redirect to /dashboard
- `PublicOnlyRoute.tsx` — redirect to /dashboard if already logged in

### Step 20 — Layout components
- `AuthLayout.tsx` — centered card layout for login/register
- `MainLayout.tsx` — sidebar + navbar + content area
- `Sidebar.tsx` — navigation menu (different links per role)
- `Navbar.tsx` — user info, avatar, logout button

## Fase 4: Auth Pages

### Step 21 — LoginPage
- Form: email, password
- Submit → panggil login() dari AuthContext → redirect ke dashboard
- Handle error: invalid credentials
- Link to register page

### Step 22 — RegisterPage
- Form: nama, email, password, jabatan, phone
- Submit → panggil register() → redirect ke login
- Link to login page

## Fase 5: Fitur Inti Karyawan

### Step 23 — DashboardPage (Personal)
- Stats cards: total hadir hari ini, minggu ini, bulan ini
- Recent 5 absensi (latest first)
- Quick action button: "Absen Sekarang" (link ke /absensi)
- Greeting with user name

### Step 24 — AbsensiPage (Check-in / Check-out)
- Check status absensi hari ini
- If no record today: show "Check-in" button
- If checked in but not out: show "Check-out" button, show check-in time
- If already complete: show "Selesai" status with times
- Optional face verification toggle before check-in
- Face verification: open camera modal → detect face → verify → proceed

### Step 25 — Face Recognition (optional integration)
- Load face-api.js models on app mount
- On check-in: capture webcam photo → detect face descriptor → save to user profile (first time) or match against saved descriptor
- Fallback: skip face verification if models fail to load

### Step 26 — RiwayatPage
- Filter bar: date range (start-end), status dropdown (hadir/terlambat/izin/sakit/cuti/all)
- Sort: by tanggal (asc/desc)
- Table: tanggal, checkIn, checkOut, status badge, faceVerified icon
- Empty state: "Belum ada riwayat absensi"

### Step 27 — PengajuanListPage
- List/table of user's pengajuan
- Columns: jenis, tanggal range, alasan, status badge (pending/approved/rejected), catatan
- Color-coded badges: pending=yellow, approved=green, rejected=red
- Empty state: "Belum ada pengajuan"
- FAB button: "Ajukan Baru"

### Step 28 — PengajuanFormPage
- Form fields:
  - jenis: radio/select (Cuti / Izin / Sakit)
  - tanggalMulai: date picker
  - tanggalSelesai: date picker (>= tanggalMulai)
  - alasan: textarea
- Validation: all required
- Submit → POST /pengajuan → redirect ke list page

### Step 29 — ProfilPage
- View mode: display all user info (nama, email, jabatan, phone, alamat)
- Edit mode: toggle form with pre-filled values
- PATCH /users/:id on save
- Avatar upload placeholder

## Fase 6: Fitur Admin

### Step 30 — HrdDashboardPage
- Stats row: total karyawan, hadir hari ini, terlambat hari ini, pending pengajuan
- Table: all karyawan (searchable by name/jabatan)
  - Columns: nama, jabatan, status hari ini, total hadir bulan ini
  - Click row → modal detail
- Section: Pengajuan Pending
  - List pending requests with Approve / Reject buttons
  - Approve/Reject → Dialog with optional catatan → PATCH pengajuan status
